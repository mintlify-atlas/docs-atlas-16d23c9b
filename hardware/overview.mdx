title: "OpenSC supported smart cards and security tokens"
description: "OpenSC supports 40+ smart card types, HSMs, and national eID cards across Linux, macOS, and Windows through a unified PKCS#11 and PKCS#15 interface."
---

OpenSC supports a broad range of smart cards, USB tokens, and hardware security modules through a driver architecture that maps each card type to a dedicated driver. When you insert a card, OpenSC reads its Answer To Reset (ATR) bytes to identify the card type and loads the matching driver automatically. Over 40 card families are supported across Linux, macOS, and Windows.

## Checking support for your card

To list all drivers compiled into your OpenSC installation:

```bash
opensc-tool --list-drivers
```

To see which card (if any) OpenSC detects in your reader:

```bash
opensc-tool --info
opensc-tool --atr
```

If OpenSC does not recognize your card, it will fall back to a generic driver. Some cards that implement PKCS#15 natively are handled through the PKCS#15 emulation layer even if no dedicated driver exists.

## Card detection via ATR

The ATR is a byte string the card sends on power-up that encodes the card's protocol and, for many cards, its product identity. OpenSC matches ATRs against a built-in table. You can view the ATR of the inserted card with:

```bash
opensc-tool --atr
```

The mapping from ATR to driver is defined in each card driver's source file. If your card has an ATR that is not yet in the table, you may still be able to use it by specifying the driver explicitly in `opensc.conf`.
